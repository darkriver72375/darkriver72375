# darkriver72375

Hey, I'm a developer who spends most of my time in the terminal and occasionally remembers to document things.

## What I actually care about

I work mainly with **Python**. Scripts, small services, data pipelines — anything that needs to run reliably without constant babysitting. I prefer code that is boring and predictable over clever one-liners that break three months later.

**Automation** is where a lot of my energy goes. If a task has been done more than twice, it should probably be a script or a systemd timer. I automate the dull parts so I can focus on the interesting ones (or at least the less dull ones).

**Linux** is home. I run it on servers and on my daily driver. Understanding how the system actually behaves under the hood makes debugging faster and prevents a lot of "it works on my machine" moments.

I also like **open source** for the practical reasons: reading other people's code teaches you patterns you wouldn't invent yourself, and contributing back (even small fixes) keeps the tools you rely on alive.

## How I work

- Prefer clear structure over magic
- Write the simple version first, then improve only what needs it
- Keep dependencies light when possible
- Document the non-obvious parts, skip the rest
